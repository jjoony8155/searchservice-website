다나와 디시전 엔진

검색은 전사 비전을 실현하는 통합 허브다. 사용자가 다나와에서 찾으면 후회 없는 선택을 할 수 있도록, 가격·스펙 데이터로 검증된 객관적 근거를 제공하는 다나와의 디시전 엔진으로 진화한다.

이 비전을 실현하려면 두 가지 전제가 필요하다.

01 검색 시장이 빠르게 변하고 있다 — 지금 움직이지 않으면 뒤처진다
02 아무리 좋은 비전도 가격비교·상품검색이라는 핵심 경쟁력이 탄탄해야 올라설 수 있다
▶ 검색 결과의 신뢰성은 사용자에게도, 그 결과를 가져가는 AI에게도 같은 가치를 만든다. 다나와는 두 청중 모두에게 같은 품질의 결과를 제공하는 것이 디시전 엔진의 본질이다.
▶ 이 방향성에 대한 4본부의 공감을 확인하는 것이 협의체 1차 미팅의 핵심 안건입니다.

왜 지금인가 — 검색 시장의 변화

키워드를 입력하고 결과를 고르는 시대에서, AI가 의도를 이해하고 실행까지 돕는 시대로 전환 중이다. 경쟁사들은 이미 빠르게 움직이고 있다.

시대 흐름

독립 앱에서 통합 허브로

지금까지 인터넷 서비스는 각자 자기 분야만 잘하면 됐다. 다나와는 가격비교를, 아정당은 통신·렌탈을, 보험은 보험사가, 설치는 설치업체가.

하지만 사용자는 한 가지 일을 해결하기 위해 여러 앱을 오가며 지친다. "이사 한 번 가는데 가전 비교, 통신 이전, 보험 변경, 설치 예약을 다 따로 해야 하는가?" 이 피로감이 누적되면서, 시장은 한 곳에서 모든 일이 풀리는 플랫폼 쪽으로 옮겨가고 있다.

2026.01 · 구글 발표
UCP (Universal Commerce Protocol)

구글이 Shopify, Walmart, Target, Stripe, Visa 등 20여 개 글로벌 기업과 함께 만든 새로운 쇼핑 표준. 사용자가 검색하다가 마음에 드는 상품을 찾으면 그 자리에서 바로 구매까지 끝낼 수 있게 한다.

이 흐름이 한국에 오면 가장 영향받는 것은 가격비교 사이트다. 사용자가 검색 결과 페이지를 떠나지 않고 바로 구매한다면, '클릭아웃' 모델 자체가 흔들린다.

▶ 다나와의 답은 두 가지다. 외부 AI 시대에는 MCP로 자리잡고(다음 박스), 축적된 가격·스펙 데이터라는 다나와만의 자산을 이 새 흐름 위에서 작동하게 만드는 것이다. 자세한 내용은 이어지는 단락들에서 풀어진다.
다나와의 현실 · 진행 중
MCP (Model Context Protocol) — 이미 운영 중

다나와는 이미 이 흐름에 대응하고 있다. 상품 검색 MCP(api.mcp.ai.cowave.kr)가 운영 중이고, 카카오 카나나 제휴도 협의 단계에 있다. AI 에이전트(ChatGPT, Claude, 퍼플렉시티 등)가 "아이폰16 최저가" 같은 질문을 받으면 다나와 MCP를 호출해서 답을 가져간다.

사용자 → AI 에이전트 → 다나와 MCP → 답

여기서 다나와가 권장한 상품이 곧 사용자에게 전달됨

▶ MCP가 검색팀에 의미하는 것

사용자는 이제 다나와 UI를 거치지 않고 AI 답을 그대로 받는다. 검색 결과의 신뢰성이 다나와의 외부 평판을 결정한다. 이것이 "검색이 결정이 됩니다"이 단순 슬로건이 아닌 이유다.

▶ 외부 AI가 던지는 쿼리를 정확히 매칭하는 것 — 다나와 의미 인프라

외부 AI가 사용자 의도("가성비 좋은 14인치 노트북", "여름에 시원한 베이지 슬리퍼")를 분해해서 다나와에 쿼리를 던지면, 다나와는 그 쿼리에 정확히 매칭해야 한다.

AI가 던진 쿼리가 다나와 데이터의 어떤 상품·태그·속성·리뷰와 연결되는지가 검색 품질을 결정한다.

즉, 다나와가 사용자 자연어를 직접 받지 않더라도, 데이터 자체에 의미 구조(태그·동의어·카탈로그 정합성)가 박혀 있어야 외부 AI가 정확한 답을 가져갈 수 있다. 이것이 다나와의 의미 인프라가 필요한 이유다.

〔 자료 안 용어 정리 〕

외부에서 "AI 검색"이라는 표현이 혼용되는데, 이 자료에서는 다음과 같이 구분합니다.

외부 AI 검색

AI 에이전트(ChatGPT, Gemini, Claude, 카나나 등)가 사용자 의도를 받아 다나와 같은 데이터 소스에 쿼리를 던지고, 그 결과를 사용자에게 답하는 것.

다나와 의미 인프라

외부 AI가 던지는 쿼리를 다나와 데이터(상품·태그·속성)와 정확히 매칭하는 능력.

다나와가 사용자 자연어를 직접 받지 않더라도, 외부 AI가 정확한 답을 가져가려면 다나와 데이터에 의미 구조가 박혀 있어야 한다.

다나와 자체 모바일 AI · 내부 채널
다나와 모바일 안의 자연어 검색 진입점 — 내부 AI 채널

외부 AI 채널(MCP)이 있다면, 다나와 모바일 안에도 사용자가 자연어로 직접 묻는 AI 검색 진입점이 필요하다. 외부 AI가 다나와 데이터를 가져가는 흐름과 별개로, 사용자가 다나와에 직접 들어와 묻는 별도 흐름이다.

두 채널이 같은 다나와 데이터를 근거로 답해야, 외부 AI를 통해 보든 다나와 모바일에서 직접 보든 사용자에게 일관된 신뢰가 만들어진다. 이것이 외부 채널과 내부 채널이 양면으로 굴러가야 하는 이유다.

▶ 구체적 구현 방식은 협의체에서 함께 정한다

자체 LLM 여부, 외부 LLM 활용, 데이터 결합 형태 같은 방법(how)은 협의체 트랙 4(개발본부)에서 본부 의견과 함께 정하는 영역이다. 검색팀이 지금 단계에서 정해 두는 것이 아니다.

네이버 검색
한국형 생태계 완결성으로 빅테크에 맞서다
왜 검색이 카페·블로그·쇼핑·뉴스 트래픽을 분배하는 입구 — 검색이 흔들리면 네이버 전체가 흔들린다. 검색의 입구 위치를 어떻게든 지키는 방어 전략.

한국어 맥락과 온/오프라인 생태계의 완결성으로 살아남았다. 글로벌 빅테크가 단기간 따라올 수 없는 로컬 생태계 장벽 구축이 핵심 전략.

네이버쇼핑
직접 경쟁자
검색-쇼핑-결제-물류 통합으로 이탈을 막다
왜 가격비교만 하면 사용자가 외부 쇼핑몰로 빠진다 (다나와 클릭아웃 모델과 같음). 결제·페이까지 흡수해서 사용자·매출·데이터를 네이버 안에 가두는 수직 통합 전략.

가격비교 영역에서 가장 큰 트래픽을 가져갔다. 다만 가격비교의 디테일과 깊이에서는 다나와가 앞선다. 규모는 네이버쇼핑이 크지만 정확성은 다나와가 앞선다. 문제는 이 차이가 사용자에게 잘 보이지 않는다는 것이다.

아마존 / 쿠팡
검색창이 곧 구매의 입구
왜 자체 물류·결제·멤버십 보유. 사용자가 가격을 비교할 이유 자체를 없앤다 ("쿠팡이면 어차피 싸/빠르다"). 가격비교 단계가 사라지면 중간 매개자(다나와 같은)도 사라지는 수직 통합 전략.

AI가 리뷰, 반품률, 만족도를 종합해 최적 상품을 골라주고, 검색 데이터가 물류 예측·재고 배치에까지 연결. 검색이 커머스 운영의 핵심 인프라.

신뢰 자산으로 살아남은 모델
왜 일본에서 빅테크와 자본·물류·기술로 정면 경쟁 불가능. 그래서 빅테크가 못 따라 하는 영역 = 객관적 비교의 깊이에 집중하는 차별화 전략. 이 길이 다나와에도 적용된다.

"카카쿠에서 찾으면 정확하다"는 평판을 지킨 것이 핵심. 가격 정확성, 제품 정보 디테일, 사용자가 납득할 수 있는 노출 순위 — 세 가지를 흔들리지 않게 유지했다. 더해 "카카쿠 리뷰어"라는 자긍심을 가진 사용자들이 한 편 한 편 장인의 손길 같은 리뷰를 남긴다. "리뷰가 곧 신뢰"가 되고, 그게 카카쿠 검색의 +α다.

이데알로 (Idealo)
AI 시대 모델
같은 위치에서 AI 시대 대응
왜 다나와와 같은 위치(2000년 설립, 클릭아웃 모델, 25년 자산)의 유럽 가격비교 사이트가, 카카쿠가 보여주지 못한 "AI 시대 어떻게 가야 하나"를 실제로 답하고 있다.

독일·유럽 가격비교 사이트. 다나와와 같은 시기(2000년 설립)에 같은 모델(클릭아웃)로 시작했다. 카카쿠가 "신뢰 자산으로 살아남는 법"을 보여줬다면, 이데알로는 "그 자산을 AI 시대에 어떻게 자산화할 것인가"를 보여준다.

ChatGPT 앱 출시 (2026.03) — MCP가 API가 아닌 사용자 경험으로. 6억 개 실시간 가격 데이터를 ChatGPT 안에 연동하여 할루시네이션을 원천 봉쇄.
"디시전 미디어(Decision Media)" 광고 모델 (2025) — 가격 중립성(최저가 정렬 그대로)과 광고 효과를 양립시키는 구조. 다나와 "디시전 엔진"과 같은 단어, 같은 구조.
▶ 카카쿠 + 이데알로 = 다나와가 가야 할 길의 두 축

▶ 그래서 다나와는 어떻게 가는가
카카쿠의 신뢰 자산을 강화한다

Positioning

검색의 새로운 포지셔닝

From 카테고리별 상대적 가격비교 도구   To 검색이 결정이 됩니다 — 다나와 디시전 엔진

01
정확한 결과

원하는 것을 제대로 찾아준다. 모델명 매칭, 형태소 분석, 카테고리 통합 검색이 정확하게 작동해야 가격비교 자체가 의미 있다.

"갤럭시S25" → 갤럭시S25가 정확히 나와야 함
"아이폰17 프로" → 정확한 모델명에 일치하는 상품 노출
02
신뢰할 수 있는 결과 — 객관적 근거 기반

다나와 디시전 엔진의 핵심. 축적된 표준화된 스펙·가격 데이터를 검색 결과의 근거로 제시한다. 일관된 기준의 랭킹으로 전 카테고리에 동일한 기준을 적용하고, 사람의 수동 개입 없이 시스템이 자동으로 운영된다. 오가닉 상품과 광고 상품이 각자 역할을 명확히 유지하며, 광고는 일부 포션으로 랭킹에 반영되는 시그널로 작동한다.

"슬리퍼" → 여러 카테고리에 걸쳐 일관된 결과
03
정확하게 매칭하는 검색

외부 AI나 사용자가 던지는 다양한 표현을 다나와 데이터와 정확히 연결한다. "가벼운 노트북"·"시원한 슬리퍼" 같은 표현이 어떤 상품·속성과 매칭되는지가 다나와 데이터의 의미 구조로 결정된다. 시스템이 사용자에게 맞춰간다.

"가벼운 노트북" → 실제로 가벼운 노트북이 나와야 함
"시원한 슬리퍼" → 색·계절·통기성 의미 매칭
04
전사 비전을 실현하는 통합 허브

검색이 신뢰를 확보한 이후, 그 신뢰를 기반으로 생활결합서비스(아정당, 보험, 다나와 스토어, 데스크테리어, 다해줌 등)를 자연스레 연결하는 통합 허브로 진화한다. 사용자의 구매 이력과 행동 데이터를 기반으로 이 사람의 상황에 맞는 서비스를 자연스레 제안한다. 이것이 전사 비전인 라이프 큐레이터를 검색이 실현하는 방식이다. 고객 데이터 연동(CRM 등)은 별도 협의를 통해 단계적으로 검토한다.

▶ 그러나 "어떻게 풀어낼 것인가"는 숙제다

각 생활인프라 서비스는 이미 버티컬 서비스로 독립 운영되고 있다. 검색이 단순히 "노출"만 함께 한다고 "통합 허브"가 되는 것은 아니다. 검색팀 단독으로 답할 수 없는 접점이다.

검색팀이 책임지는 영역
  • 사용자 의도를 자연어로 받아내기 ("이사 준비")
  • 의도에 맞는 다나와 자산(상품·서비스) 매칭
  • 검색 결과에서 관련 서비스 진입점 자연스레 제공
함께 정해야 할 영역 (협의체 숙제)
  • 우선 통합 대상 서비스는 무엇인가
  • 각 서비스와의 연결 깊이 (단순 링크 / 진입점 연동 / 결제 통합)
  • 각 서비스 사업부와의 데이터 연동 범위
  • 사용자 여정의 단일성 수준 (어디까지 다나와 안에서)
  • 회원·포인트 통합 시점

구체적인 논의는 본문 끝 "결정이 필요한 사항 06"으로 이어진다.

Strategy

전략 — 어디부터 풀어갈 것인가

포지셔닝을 실현하기 위한 두 가지 전략. 모든 전략의 출발점은 1번이다.

01
사용자 의도에 부합하는 랭킹 강화 핵심

모든 전략의 출발점이다. 여기가 탄탄해야 나머지가 가능하다.

  • 일관된 기준의 랭킹 — 전 카테고리에 동일한 기준 적용. 다중 카테고리·통합 검색에서 일관된 결과를 보여준다.
  • 자동화된 구조 — 사람의 수동 개입 없이 시스템이 운영된다. 카테고리 간·시점 간 기준이 일치한다.
  • 오가닉·광고 역할 분리 — 오가닉 상품과 광고 상품이 각자 역할을 명확하게 유지한다. 광고 집행은 일부 포션으로 랭킹에 반영되는 시그널로 작동한다.
02
새로운 검색 진입점 — 통합 허브 단계에 검토

기존 검색창은 그대로 유지하면서, 데이터의 의미 구조를 단계적으로 풍부하게 만든다. 사용자가 자연어로 검색하는 진입점은 통합 허브 단계에서 본부 의견과 함께 검토한다.

이 자연어 진입점은 자체 LLM 구축이 아니다. 외부 LLM(OpenAI·Anthropic·네이버 클로바 등)을 활용하되, 다나와 내부 MCP·데이터와 결합하는 방식이다. 자체 모델 학습 부담을 줄이면서, 외부 AI가 흉내 낼 수 없는 다나와 데이터 결합이 차별점이 된다. 구체적 구현 방향은 개발본부와 함께 검토한다.

UI/UX Direction

UI/UX 방향 — 5가지 시안

검색이 결정을 돕는다 — 사용자가 결정에 필요한 정보를 한 화면에서 받을 수 있도록.

👁
본 와이어프레임은 컨셉 수준의 예시입니다. 실제 디자인은 본부 협의로 단계적으로 진행됩니다. 핵심은 "검색이 결정을 돕는다"는 원칙. 사용자가 스크롤 전에 결정에 필요한 정보를 받을 수 있는 구조.
01 · To-be 검색 시 AI 구매팁 노출
AI 구매팁이 결정에 필요한 정보를 첫 화면에 제공
"이 카테고리 어떻게 골라?" 답을 검색 결과 안에서 받음
콘텐츠팀 가이드가 결정 순간에 닿음
02 · To-be 검색결과 — 가격추이·AI 평가·AI 리뷰 신호
검색결과에서 가격추이·AI 평가·리뷰 신호가 한눈에
"지금 살까 말까" AI가 즉답 (구매 좋은 시점 / 가격 상승 / 신제품 임박)
클릭 없이도 비교할 수 있는 카드 — 결정에 필요한 정보가 첫 화면
다나와 자산(가격추이·AI 설명·리뷰 요약)이 결정 순간에 닿음
03 · To-be 모바일 AI 검색 첫 페이지
기존 검색창과는 별도의 새 AI 검색 씬으로 작동
"무엇이든 물어보세요" 자연어로 시작
인사·안내가 밝고 친밀한 톤
추천 질문이 다나와 영역(상품·서비스)과 연결
AI가 직접 답을 만들어 검색의 진입 다양화
04 · To-be 자연어 검색 — 상품·콘텐츠·서비스 통합
의도 하나로 상품·콘텐츠·서비스 동시 매칭
검색이 통합 허브로 작동하는 모습
생활결합서비스(아정당 등)가 자연 연결
05 · To-be 검색 결과 없을 때 — AI 검색 자연 유도
막힌 경험을 AI가 풀어주는 자연 유도
"결과 없음" 대신 다음 행동 제안
검색 막다른 길이 새로운 시작점이 됨
▶ 협의체 숙제 — 함께 다듬어 갈 영역 이 5종은 검색팀이 그린 첫 시안입니다. 각 본부의 의견을 받아 단계적으로 다듬어 갑니다. 구체적 논의는 본문 끝 결정이 필요한 사항 08번으로 이어집니다.

02
사용자 의도에 부합하는 랭킹 — 광고 반영 비중 합의

다나와 검색이 사용자 의도에 부합하는 결과를 보여주기 위해 랭킹 구조를 어떻게 합의할지 함께 정합니다. 오가닉 상품과 광고 상품의 역할을 명확히 유지하면서, 광고가 일부 포션으로 랭킹에 반영되는 수준을 본부 간 협의로 조율합니다.

참여비즈니스솔루션본부 + 서비스기획본부(검색팀) + 큐레이션본부
함께 정할 것행동 데이터 중심 원칙 수용 / 광고 비중의 구체적 선 / 본부 간 조율 방식
03
카테고리별 검색 요구사항 우선순위

카테고리별 검색 요구사항을 수집하고 도입 순서를 합의한다.

주관큐레이션본부
함께 정할 것다중 카테고리 키워드(슬리퍼·샌들 등) 처리 방식 / 카테고리별 최적화 뷰 도입 순서 / 검색 결과 품질 기준
04
데이터 수집 범위 합의

개인화·의도 이해·생태계 연결을 위한 데이터 수집과 정형화 범위를 합의한다.

주관개발본부 + 서비스기획본부(검색팀)
함께 정할 것모바일 행동 데이터 수집 / 회원통합·통합포인트 연동 시점(별도 검토) / CRM 연동 범위(별도 검토)
05
협의체 운영 체계 확정

협의체가 지속 가능하게 굴러가도록 운영 체계를 고정한다. 노션을 통한 비정기 의견 수렴 + 필요 시 정기 미팅으로 조율을 기본 틀로 한다.

함께 정할 것노션 비동기 의견 수렴 방식 / 정기 미팅 소집 기준 (안건 무게, 합의 필요성) / 합의 내용 기록 책임자 / 본부 간 의견 충돌 시 조율 방식
06
통합 허브 — 생활결합서비스 연결 방식 합의

검색이 생활인프라 서비스(아정당·보험·데스크테리어·다해줌·스토어)를 어떻게 연결할지 함께 정의한다. 각 서비스가 버티컬로 운영되고 있어 단순 노출 통합만으로는 "통합 허브"가 되지 않는다. 검색팀 단독으로 답할 수 없는 접점이다.

주관각 버티컬 서비스 담당자 + 서비스기획본부(검색팀)
함께 정할 것우선 통합 대상 서비스 / 연결 깊이(단순 링크 → 진입점 연동 → 결제 통합) / 각 서비스 사업부와의 데이터 연동 범위 / 사용자 여정의 단일성 수준 / 회원·포인트 통합 시점
07
상품 자산을 결정 순간에 닿게 하는 방식 합의

다나와가 오랜 시간 쌓아온 상품 자산(구매가이드·기획전·리뷰·가격 추이)이 검색 결과·상품 페이지에서 잘 보이지 않는다. 자산이 결정 순간에 닿아야 "검색이 결정이 됩니다"이 완성된다. 06번이 "서비스 영역 통합 허브"라면, 07번은 "상품 영역의 통합 허브"다.

주관콘텐츠팀 + 큐레이션본부 + 서비스기획본부(검색팀)
함께 정할 것검색 결과 리스트에 자산 노출 방식 / 상품 카드 자산 신호의 종류와 우선순위 / PDP 자산 통합 형태 / 각 자산의 업데이트 주체와 책임
08
UI/UX 방향 의견 수렴

검색 결과·상품 페이지의 UI/UX는 지금 확정하기 어렵다. 각 본부가 명확한 의견을 가지고 있을 가능성이 높고, 함께 논의해야 다나와다운 모습이 나온다. 별도 트랙으로 의견 수렴 → 단계적 반영이 다나와에 맞는 방식.

주관서비스기획본부(검색팀) + 전 본부
함께 정할 것의견 수렴 방식(노션 비동기 / 별도 세션) / 현재 UI의 불편한 지점 / 각 본부가 그리는 이상적 모습 / 반영 우선순위
이 안건들은 검색팀이 일방적으로 제시하는 결론이 아니라, 4본부가 함께 구체화해갈 사항들이다. 각 본부의 관점과 현장 상황이 반영되어야 실제로 굴러갈 수 있다.
